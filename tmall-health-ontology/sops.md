# 分析套路 SOP（人的经验 → 可执行流程）

> 用途：把老员工"怎么看数、怎么诊断"的隐性套路显性化，供 `diagnose_metric_change`、
> `generate_weekly_report` 等编排工具执行。这是最容易被漏掉、但对 agent 质量提升最大的材料。
>
> 写法要求：每一步写清 **用什么工具、看什么指标、判断标准是什么、下一步去哪**。
> 判断标准尽量给阈值（哪怕是拍脑袋的初始值，跑起来再调）。

---

## SOP-1：GMV 下跌诊断（示例，已可执行）

**适用**：任何对象（店铺/品牌/类目）的"GMV 为什么跌了"。
**输入**：对象、当前周期、对比周期（默认环比；大促期间用活动阶段对齐）。

| 步骤 | 做什么 | 工具/指标 | 判断标准 | 结论走向 |
|------|--------|-----------|----------|----------|
| 1. 定口径 | 确认时间窗、对比基准、GMV 口径 | conventions | — | 口径不清先反问 |
| 2. 大盘对比 | 对象跌幅 vs 行业大盘跌幅 | query_metrics: pay_gmv（对象 + 大盘） | 对象跌幅 ≤ 大盘跌幅 × <1.2> → 判定"行业性波动" | 行业性 → 直接出结论；否则继续 |
| 3. 量价拆解 | GMV = 买家数 × 客单价，看哪个掉了 | pay_buyer_cnt, atv | 变化贡献度 >60% 的一侧为主因方向 | 买家数掉 → 步骤4；客单掉 → 步骤6 |
| 4. 渠道拆解 | 买家数按渠道拆 | query_metrics group_by=channel: uv, pay_rate | 单渠道贡献跌幅 ><50%> → 锁定渠道 | 搜索掉 → 看 search_uv 与关键词；付费掉 → 看投放预算（TODO 需投放数据源） |
| 5. 商品拆解 | 按商品拆，看头部集中度 | query_metrics object_type=item, order_by pay_gmv | Top10 商品贡献跌幅 ><70%> → 锁定单品 | 单品问题 → 步骤7 |
| 6. 价格检查 | 客单下跌：大促透支/优惠力度/结构变化 | atv 分商品; campaign 日历 | 大促后 <2周> 内 → 优先判"大促透支回落" | 出结论 |
| 7. 单品体检 | 下架/断货/涨价/差评/竞品截流 | get_object_profile(item); refund_rate | item_status≠在售 或 refund_rate 环比 +<X>pp → 直接主因 | 出结论 |
| 8. 输出 | 结构化结论 | — | — | 见下方输出模板 |

**输出模板**：

```
结论：<对象> <周期> GMV 环比 -X%，主因是 <维度=取值>（贡献跌幅的 Y%）。
证据：
  1. 大盘对比：大盘 -a%，本对象 -b% → <行业性/自身问题>
  2. 量价：买家数 -c%（主因方向），客单价 -d%
  3. <渠道/商品> 拆解：<锁定的具体项及数据>
建议（仅供参考）：<1-3 条，对应主因>
数据说明：口径 <支付GMV，不剔退款>，数据截至 <ds>。
```

## SOP-2：周报模板（示例骨架）

**适用**：`generate_weekly_report`，范围 = 请求人负责的类目/商家。

1. **大盘速览**：pay_gmv / uv / pay_rate / new_buyer_ratio，环比+同比，一句话定调
2. **异动点**：跌幅或涨幅 Top3 的 <类目/品牌>（阈值：环比变化 ><15%>），各附一行 SOP-1 简版归因
3. **商品动态**：本周 GMV Top10 与新进榜商品；断货/下架预警（item_status 变化）
4. **大促节奏**（若处于 campaign 周期内）：对比活动日历同阶段表现
5. **下周关注**：由 2/3 的异动点自动生成待办建议
